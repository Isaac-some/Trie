# 传输路径分组（本地版）

面向 CSV 的本地路径拆分与传输清单生成工具。GitHub 只保存本项目代码；CSV、路径树、任务状态和导出文件只在运行工具的电脑上处理，不会上传到 GitHub、阿里云或其他第三方服务。

## 一句话启动

先安装 [Node.js 22 LTS](https://nodejs.org/)，再进入项目目录执行：

```bash
npm run local
```

这条命令会依次完成：

1. 检查 Node.js 版本和依赖状态。
2. 首次运行时自动安装项目依赖。
3. 构建前端。
4. 启动本地服务，并提示实际访问地址。默认从 `http://127.0.0.1:8787` 开始；如已被占用，会自动使用下一个可用端口。

终端中出现“服务已准备就绪”后，在浏览器打开该地址即可使用。按 `Ctrl+C` 可停止服务。

## 环境要求与检查

唯一必需的系统依赖是 **Node.js 22 或更高版本**，安装包自带 npm。不需要 Docker、云服务器、数据库、账号、访问密钥或任何浏览器扩展。

只检查本机环境、不启动服务：

```bash
npm run doctor
```

它会显示 Node.js、npm、项目依赖、前端构建和本地访问限制的状态。

## 数据如何留在本机

- 服务默认只监听 `127.0.0.1`，同一 Wi-Fi、公司局域网和互联网中的其他设备无法访问。
- 浏览器上传的文件会按 8MB 分片发送给**本机服务**，不会离开电脑。每片都带 SHA-256 校验；合并完成前原分片不会删除。
- CSV、生成的目录树和导出文件写在操作系统的临时目录中；切换标签页或刷新页面不会清理当前会话，连续 1 小时无活动的会话会自动清理。
- 项目不会收集遥测信息，也不会把文件内容、文件名或导出结果发送给 GitHub。
- 请勿把 CSV、导出结果或临时数据目录提交到 Git；`.gitignore` 已排除常见本地数据目录。

## 交给 Codex / ChatGPT 本地运行

把本仓库的 GitHub 链接和下面这句话一起交给 Codex / ChatGPT 即可：

> 请克隆这个仓库，确认本机有 Node.js 22 或更高版本，在仓库根目录执行 `npm run local`，并在本机打开服务。不要使用 Docker、云服务或公网隧道，也不要上传 CSV。

仓库中的 `AGENTS.md` 也包含同样的本地运行与隐私约束，因此不需要额外安装 Skill。

## 功能与限制

- 可同时选择多个 CSV；每个文件独立选择路径列、生成路径树和导出结果。
- 单个 CSV 最大 500MB；同一次页面会话的所有 CSV 合计最多 512MB。上传可在中断、刷新后重新选择同一文件继续。
- CSV 按行读取，不会将整份文件加载进内存；每个目录最多保留 20 个文件名样本。
- 后台任务默认逐个处理，避免多个大文件同时占满电脑内存和磁盘。需要调整时可设置环境变量 `MAX_CONCURRENT_JOBS`，普通电脑建议保持默认值 `1`。
- 常见的 50MB 以下 CSV 建议预留 1GB 可用磁盘；单个 500MB CSV 建议预留至少 2GB。合并阶段会短暂同时保留分片和已合并文件，以保证中断时可恢复；路径树或导出结果很大时请预留更多空间。
- 每天处理 100 个 50MB 以下 CSV 没有额外的存储要求：文件在会话结束后清理，后台任务也默认逐个执行。若 100 个文件都是 200MB，则应分批运行并预留更多处理时间。

## 开发模式

仅在修改界面时使用。一个终端运行后端：

```bash
npm run start
```

另一个终端运行前端热更新：

```bash
npm run dev
```

开发模式下前端地址由 Vite 输出；它仍只把 `/api` 请求转发给本机的 `127.0.0.1:8787`。
